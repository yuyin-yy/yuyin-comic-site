## 我的追漫页新增尾屏诗句（滚动浮字，仅本地未推送）

**参考**：nexmoe.com 首页那段「谁怕？一蓑烟雨任平生」。
用 curl 抓了一次首页 + 一次 `_astro/Poe.astro_*.js`（共 2 个请求，没有批量抓取），
确认其实现是 **GSAP ScrollTrigger**：

```js
gsap.timeline({ scrollTrigger: { trigger: elePoe, start: 'center center',
  end: 'bottom+=70% center', scrub: 1, pin: true, pinSpacing: true } })
  .to(第一列, {opacity:1}) .to(第二列,…, '+=0.5') … .to([前三列], {opacity:.3}, '<')
```
每个元素是一整列（不是逐字），`.poe{writing-mode:vertical-lr}`。

**本项目实现**（零依赖，不引 GSAP）：
- `public/js/ui/poem.js`（新增，约 200 行）
  - `.poem` 撑高 260vh，`.poem-pin` 用 `position: sticky; top:0; height:100svh` 等价于 `pin:true`；
  - 进度 = `-rect.top / (sectionH - pinH)` 换算成 0~1，rAF 节流后逐帧写样式；
  - **逐字**拆 span（`.poem-ch`），列内按序号错开起点 → 像被一笔一笔写出来；
  - `smooth()` = smoothstep，替代 GSAP 的 power2.out；
  - 前几列在主句浮现时压到 42%（0.58 系数），最后一列不压；
  - IntersectionObserver `rootMargin:400px` 挂/摘 scroll 监听；
  - `apply()` 缓存上一次写入值，值没变不碰 DOM。
- `public/css/pages.css` 追加 153 行「尾屏诗句」段：竖排 `writing-mode: vertical-rl` +
  `.poem-stage{flex-direction:row-reverse}` 把 DOM 第一列摆到最右（右起阅读）、
  细点阵背景（radial-gradient 24px）、底部 2px 进度线（brand red）、
  `prefers-reduced-motion` 整段静态化、断点 1080/720/460 + `max-height:560`。
- `public/my.html`：在「你可能还想看」之后插入 section；视觉部分 `aria-hidden`，
  整首诗由 `.sr-only` 段落给读屏。
- `public/js/app.js`：`if (YY.poem) YY.poem.init();`（守卫式，其他页面无节点直接返回）。

**踩到的两个坑**：
1. 主句 7 字竖排，高度必须跟视口挂钩，否则 1280×720 会顶到底部撞上署名 →
   `font-size: min(76px, 8.8vh)`。
2. reduce 分支里 `.poem-pin` 仍是 flex row，署名会被摆到诗的右边 →
   该分支补 `flex-direction: column`。

**验证**：1440×900 / 1280×720 / 1024×768 / 390×844 四档 + reduce 模式截图核对；
全站 7 页 × 2 视口无 console 报错、无横向溢出。

## 导航随滚动方向收起/放回（仍仅本地）

**需求**：尾屏插画被顶部导航压掉一条，要求「下滑隐藏、上滑显示」。

**实现**（`layout.css` + `ui/nav.js`，全站生效）
- `.site-header.is-hidden { transform: translate3d(0,-100%,0) }`，过渡 0.36s；
  只动 transform 不动布局，收起时下方内容零跳动（实测 docHeight 与像素位置不变）。
- 首页 `body[data-page="home"] .site-header` 原本整套覆盖 transition，**必须把
  transform 补进那串列表**，否则首页收起是硬切。
- JS 塞进已有的 scroll 处理器里（不新增监听）：`dy = y - lastY`，
  `|dy| < 4` 直接 return 且不更新 lastY（把细碎滚动累积成一次判断，避免抖动）；
  `y <= 96` 强制露出；`dy > 0` 收起、`dy < 0` 放回。
- 三个例外不收：抽屉 `#navDrawer.open`、焦点在 `#app-nav` 内（搜索框正在输入）、
  `prefers-reduced-motion`。另加 `focusin` 立即放回，防 Tab 焦点落到屏幕外。

**实测**：真滚轮下滑收起 top=-68、上滑恢复 top=0；顶部 80px 内下滑不收起；
抽屉展开 / 搜索框聚焦 / 减少动效 三种情况均不收起；
7 页 × 2 视口回归无报错、无横向溢出（Login.html 没有 nav，测试脚本需判空）。

## 罗生门光尘层（2026-11-08 夜）

用户："页面不点击的时候纯静态，看着不好看，可以加上粒子效果，门、水面、天空都加。"

**新增 `public/gate/gate-fx.js`（~480 行，Canvas 2D）**，与 `gate.js` 同目录，
`index.html` 在 gate.js **之前**引入（gate.js 一 init 就 layout → setDoor）。

分层与粒子类型（k）：1 天空浮尘 / 2 水面碎光 / 3 门缝光尘 / 4 大虚焦光斑 /
5 水面波纹 / 6 门框柔光（i=0 那颗是门缝光柱）。桌面约 280 个，手机（lite）约 100。

**踩坑记录（都是靠截图 + 差分验证出来的，别凭感觉调）**：
1. 一开始全用同一张柔和渐变贴图 → 完全看不见。64px 的渐变缩到 2px 时，
   一个输出像素会把整张图平均掉，0.4 的 alpha 只剩 0.05。
   改成 `dot`（0.45 半径内实心核 0.98）+ `halo`（柔）两套贴图才解决。
2. 光有 `dot` 还是看不见：径向渐变的中段太虚，视觉直径只有设定值的 ~0.72。
   天空粒子最终给到 4~13px（幂分布，多数细小、少数大）。
3. 亮背景上**白点 = 看不见**（白叠白）。天空混 30% 金色 `255,214,140`、
   门的柔光只镶在门框上（那里背后是深色建筑）才显形。
4. `.gate::before` 的压暗层把天空粒子吃掉了：顶部 0.46 → 0.3、底部 0.52 → 0.4。
   返回按钮自己有 backdrop-filter + 半透明底，不靠这层撑。
5. 水面高度不能写 `H*0.4`：cover 裁切时比例会变，改成按门反推
   `door.y - door.h*0.05`（原图水面比门顶高约 0.05 个门高）。
6. 桌面视口面积是手机的十几倍，数量必须分开给，否则密度差一截。

**验证方法**：差分（截图 - 原图）看粒子到底加了多少亮度；
`--eval` 直接往 canvas 画红圆 / 白点，确认合成链路和"多大尺寸才可见"。
结论：6px 实心点 alpha 0.85 在天空和建筑上都清晰，2-3px 的点等于没有。

**联动**：`gate.js` 的 `layout()` 调 `GateFx.setDoor({x,y,w,h})`，
`open()` 调 `GateFx.burst()` —— 推门时门缝的光炸开、浮尘被往外吹。
`prefers-reduced-motion` 下 CSS `display:none`，脚本也不启动（实测 probe 确认）。
1440/1920/820/390 四种视口 + 推门瞬间都截图核对过，rAF 实测 60fps。

**tools/shot.js 新增 `--reduce`**：用 `Emulation.setEmulatedMedia` 模拟
prefers-reduced-motion，用来验收降级路径。注意 `--wait` 取**第一个**匹配，
`--eval` 前后都会用它，所以"操作后多久截图"只能靠它一个参数。

## 罗生门 · 环绕光环重做（2026-11-08 深夜）

用户："只有部分粒子，运动很慢，水面和天空也不会动，门也没有之前那个网站那样有粒子环绕。"

**三个真问题，其中两个是验证工具在骗人：**

### 1. `tools/shot.js` 三个致命缺陷（都踩了很久才发现）
- **后台页 rAF 暂停**：CDP 新建的 target 是后台标签，`requestAnimationFrame`
  和 CSS 过渡都不跑。截出来永远是第一帧，两帧差分会得到「天空水面变化 0.00%」
  这种假结论，害我反复调粒子参数。→ 加 `Page.bringToFront`。
- **`--wait` 只挂在 `--eval`/`--click` 上**：单纯截图会在导航后固定 1.8s 就按快门，
  带 `opacity` 过渡的图层（`.gate-fx` 要 1.55s 才淡入完）全是透明的，
  于是「还在淡入」被误判成「根本没画」。→ `await sleep(WAIT)` 无条件执行。
- **Chrome 复用 user-data-dir 会缓存 js/css**：改完参数截图完全没反应
  （粒子数一直停在旧版本）。→ `Network.setCacheDisabled`。
- 顺带加了 `--shots N --gap ms` 连拍，用来做同一次加载的帧间差分
  （不同次加载粒子是随机的，差分完全失真）。
- probe 从截图后挪到截图前，保证看到的状态就是画面上的状态。

### 2. `sizeCanvas()` 在 CSS 未生效时拿到 300×150
`canvas.clientWidth` 在样式表还没应用时**返回 canvas 的内在宽度 300，不是 0**，
所以 `|| window.innerWidth` 兜底救不到，画布被按 300×150 建起来再被 CSS 拉伸，
所有粒子坐标全错。→ 小于视口九成的值一律不认。
连带 `setDoor` 可能比 `gate-fx.js` 先跑（`if (window.GateFx)` 落空，door 永远 null，
水面/门/环绕三层都建不出来，只剩天空 157 颗）—— 加 `hasDoorParts` 补建 +
200/800ms 两次 `dispatchEvent(new Event('resize'))` 兜底。

### 3. 加光混合把金色顶成纯白
一整层都用 `globalCompositeOperation = 'lighter'`，金色叠在白门板、浅蓝天空上
会被加到纯白 —— 亮背景上白点等于隐形，这是「画了 16000 个不透明像素却看不见」
的真正原因。→ **分两遍画**：柔光（大光斑/光带/门框光）继续 `lighter`，
实点（浮尘/水面碎光/门缝光/环绕珠）改 `source-over`，保住自己的颜色。

### 环绕光环怎么做（gate-fx.js 的 k=9）
不是散点，是**丝带**：一条 = 22 颗珠子沿轨道排开、共享同一个角度和呼吸相位
（相位必须挂在 tape 上，各自闪烁会把弧切成碎点），头亮尾淡。
- 外圈 7 条（手机 6 条）：rad 常驻 0.9~1.04、几乎不内收，负责那一圈明确的光环；
  **rad 必须收拢**，一散开就有几条缩到门内，环上露出缺口。
- 内流 3 条：rad 从 0.3 滑到 0，被门缝吸进去，到缝口换个角度重来。
- 轨道：横向 1 个门宽、纵向 0.72 个门高（≈184 对 ≈268）。门很瘦长（184×372），
  纵向半径必须超过半个门高，否则整条轨道压在门板上，只是「门上有几个点」。
- 丝带角度**按角度均匀铺开**（不是随机），否则全挤在一侧。
- 珠子用 `orb` 贴图：亮核 + 一圈淡暗边（alpha 0.34）。纯金点在暖米色插画上
  是同一个色系，看着像脏点；有暗边才能在浅背景上「压」出轮廓。
- 珠子尺寸必须满足 **间距 < 可见直径**（球的有效直径只有设定值的六成）。
  桌面 11~15px、手机 6.5~9px（手机轨道周长没短多少，用同一尺寸会挤成粗链）。

### 运动
- 所有速度都是 px/秒。最早按「每帧 0.05px」给，等于每秒 3px，走完一屏要 8 分钟，
  看上去就是没动。现在天空 -19~-6、水面 ±16 + 缓流、门缝光 -26~-8、环绕 0.28~0.6 rad/s。
- 加了两股**全局气流** `skyWind()` / `waterFlow()`（所有粒子共享），
  「整片空气在动」才感觉得到；单颗各飘各的只像零星闪烁。
- 天空加流雾层（7 团 260~720px 的大光斑横着飘），纯靠小浮尘太细。
- 水面加波光带（9 片 200~620px 的极扁光带），补「整片水在晃」。

### 数量与性能
桌面 532 颗、手机 300 颗（`lite = on || W <= 720`，小屏初始就用轻档）。
两种视口 rAF 实测都是 60fps。`drawImage` 外面包了 try/catch，一颗坏贴图
不会让后面所有层一起消失（`window.__fxErr` 留错误信息）。
新增 `GateFx.debug(k)` 调试出口，`--probe "GateFx.debug(9).pts"` 可以拿到
某一层每颗粒子的坐标，配合 Python 画到截图上核对「该在哪 / 实际在哪」。

## 首页「最近更新」改成封面球（js/ui/orb.js + css/orb.css）

参考 foreverblog.cn 首页的照片球（`/assets/js/site-v10/sphere.js`）：黄金角
（Fibonacci sphere）把封面均匀撒在球面，每张卡片贴在球面的切平面上。
`translate3d(px,py,pz) rotateY(atan2(x1,z2)) rotateX(asin(-y2))`，舞台给 perspective。

### 结构
- `public/js/ui/orb.js`：`YY.orb.create(host, {items, cols, onMode})`，
  返回 `setMode/toggle/mode/progress/relayout/destroy`。卡片 `<a>` 直到详情页。
- `public/css/orb.css`：舞台、卡片、标题、提示条 + 自己的断点（尺寸仍由 js 算）。
- `index.html` 第 4 个 section 由 `.grid` 换成 `.orb`，标题右侧加「球体/网格」分段按钮；
  `responsive.css` 删掉了 `.home-latest{display:none}`（手机上也保留球）。

### 几个踩过的点
- 卡片**不能加投影**：二十多张的阴影互相盖，球糊成一团；纵深只用一层
  `#0c0e14` 遮罩按 z 变透明度（正面 0 → 侧面 0.34 → 背面 0.76）。
- 球越密越像球：桌面 48 张（0.42R 宽）、1080 42、900 36、≤720 32（0.46R）。
  20 张时是一堆散落的卡片，不是球。
- 透视别太陡：P=3.4R（原来的 2.4R 让最近的一张放大 1.7 倍，像纸堆）。
- 舞台平铺时会变高，**球心必须固定在「球体高度」的一半**（`world.style.top = cy`，
  perspective-origin 用 px），否则盒子一长球就往下漂。
- 球心还要给 TILT 留余量：`ax=-0.1` 会把前半球压低 ~0.1R，R 取 `cy*0.76` 才不顶到底边。
- 平铺只铺 4 行（窄屏 6 行），多出来的封面**原地淡出**（`.is-out`）——
  飞向球心会正好压在第一行网格上；48 张全摊开有 3600px 高。
- 滚轮在舞台上把 `prog` 从 0 推到 1（每格 0.19），两端交给页面滚动；
  过渡用 `1-0.93^k` 追，约 0.9s，和 foreverblog 的 960ms 节奏接近。
- 拖动惯性 `vy` 是「rad/帧@60」，要 clamp（±0.12），否则一次快甩把球转飞。
- 拖完会补一个 click，靠 capture 阶段 preventDefault 拦掉，不然会跳详情页。
- 球体状态所有卡片 `tabIndex=-1`（48 个链接会把键盘用户困住），摊平后才可聚焦。
- 封面 `loading="lazy"`：首屏 0 张，滚到附近才取（实测 48/48 加载）。
- 实测无头软件渲染 31fps，真机有 GPU 应更高；球不在视口内时 rAF 空转返回。

## 封面球第二轮：减量 + 去穿模 + 丝滑度（用户反馈「穿模、旋转卡」）

### 数量与穿模
- 球面 N 个点的相邻间距约 `R·√(4π/N)`：48 张时只有 0.51R，小于卡片高 0.56R，
  相邻两张必然互相插进去。**40 张时 0.56R，刚好贴住**。改后仍嫌密就继续减，
  但别低于 32（会漏出空洞）。
- 分档：桌面 40 / 1080 36 / 900 32 / ≤720 28；卡宽 0.42R → 0.40R（手机 0.44R）。
- 切平面倾斜只取 **0.82**：完全贴合时相邻两张平面在球面处相交，边缘卡侧成一条线
  插进邻卡，这就是「穿模」的观感来源；收到 0.82 后仍保留立体感。
  （试过 0.62，球明显变扁，不要。）
- `sc = t.s * (1 - z2 * 0.07)`：透视会把正前方那张放大 1.3 倍，回缩一点避免
  「一张卡跳出来」。透视 P 从 3.4R 放到 4.2R。

### 卡顿的三个真凶（都不在 js 计算上，全在样式/合成）
1. **ResizeObserver 无脑重排**：模式切换时 `.orb` 的 height 有 0.7s 过渡，
   RO 每帧回调 → `layout()` → 40 张卡全量重写 width/left/fontSize + `lastT=''`
   强制下帧重画。**改成只认宽度**（`Math.abs(w - lastW) < 2` 直接 return）。
2. **球体状态下的 hover**：鼠标划过卡片会触发 `.orb-shot { transform: scale }`，
   一路扫过几十张 = 几十个 0.32s 过渡。**hover 效果只留给 `.is-grid`**。
3. **每帧写 veil opacity**（40 次）会让卡片里的图片跟着重新混合。给 `.orb-veil`
   加 `will-change: opacity`，单独提一层走合成器。

### 拖动手感
- 原来 `st.vy = clamp(dx * kk, ±0.12)` 在**拖动过程中**就截断：鼠标甩快时单次
  move 的 dx 很大，被 clamp 掉 70% 位移，表现就是「球跟不上手」。
  改成拖动时原样累加，**只在 onUp 时** clamp 惯性。
- 松手前停住超过 90ms 就不甩出去（`D.t` 记录最后一次 move 时间）。
