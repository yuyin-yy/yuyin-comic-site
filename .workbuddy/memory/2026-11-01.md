   不需要任何额外环境变量，Python 启动即生效。

## 用 Scrapling 补齐 590 部作品的详情（401 → 0）

**背景**：老链路 `scrape_guazi.py` 走 urllib，详情页一请求就 403（TLS 指纹与 UA 对不上），
590 部里有 401 部只有列表信息（无章节 id / 无简介）。装完 Scrapling 后重开这条线。

**新增 `tools/scrape_scrapling.py`**（复用 `scrape_guazi.parse_detail`，解析口径不变）
- 防风控四件套：单会话复用 → 1.8~3.2s 抖动间隔 → 每 35 个请求长休 20~30s →
  403/429 分级冷却 90/240/480/900s 并切换 impersonate 指纹，连续 3 次收工。
- 断点续跑：已存在的 `.tmp/gz/details/<id>.json` 直接跳过，随时中断都不丢进度。
- 失败留痕：`.tmp/gz/failed_ids.json` + `.tmp/gz/scrapling_state.json`。
- 实测：26.4 分钟补 397 部，全程只有 1 次风控判定，且是**误判**
  （HTTP 200 但正文含「验证」二字）。已把判定收敛为「状态码 + `<title>` 关键词」，
  重跑把最后 1 部补上，最终 **590/590 全部拿到详情**。

**结果**
- `data/guazi_comics.json` 590 部 → `build_data.py` → `public/js/data.js`（1012KB，gzip 255KB）。
- 可直接开读 590 部、评分覆盖 590、简介覆盖 590、平均 109 话；`pending` 计数 0。
- 章节 id 全部可直达原站 `chapter.php?id=`，`total` 取完整章节数。
- 遗留：124 部 `region` 为空（来自 sort=hits 入口），需翻全 city 分类页才能补，暂未做。

**改动的代码**
- `tools/build_data.py`：新增派生字段 `pending`（=1 表示章节未抓到），排序/统计一并输出。
- `public/js/pages/detail.js`：阅读入口改为 `hasChs` 分支 —— 有章节走 `readUrl` 外链；
  没有章节一律跳 `404.html?from=pending&id&t`，文案「内容待补全」；`#dSrc` 原站兜底只在有章节时显示。

  无参数时仍是原 404。
- `public/css/pages.css`：补 `.detail-src[hidden]{display:none}`（`inline-flex` 会盖掉 `[hidden]` 默认样式）。
- `tools/guazi_loop.py`：标注**已弃用**（其依赖的 urllib 链路已无法取详情）。
