# 2026-11-05

## 首屏加载优化（提交 9a109c9 / 62a0da4 / d9f1425，已推送）

**用户反馈**：网站打开很卡、图片加载很慢。

**实测根因**（playwright-core + 本地 chromium 真实浏览器测量，1440×900）：
- 优化前 DOMContentLoaded **20.5s**，15 秒时 38 张封面还在 pending。
- GitHub Pages 直连 185.199.109.153（Fastly 东南亚）：单请求 TTFB 0.9~1.4s，
  data.js（gzip 262KB）2.2s，封面单张 2.3s，有效带宽 27~118KB/s；
  20+ 请求并发抢同一条管道，总字节数基本等于总耗时。
- 首屏原本要下 ~1.1MB（data.js 262 + 首屏图 105 + 20 张封面 620 + CSS/JS 60）。

**改动**：
1. **数据拆包**（build_data.py）：desc + chs 移到 `js/data-detail.js`，只有
   `index02.html` 引。`data.js` 由 1012KB/262KB(gzip) 降到 327KB/**50KB**，
   详情页的 192KB 不再压在首页。core.js 新增 `YY.detailOf(id)`，
   detail.js 在 init 里把 `{desc, chs}` 合并回 item，下面代码一行没改。
2. **封面懒加载**（card.js）：img 用 `src=YY.blank`（1x1 透明 GIF）+ `data-src`，
   IntersectionObserver `rootMargin:400px` 才赋值。原生 `loading=lazy` 的预取
   距离约 1250px，首页 20 张全在范围内等于没懒加载。rank.js 同步改造。
3. **封面重压**：q82→q72，15.0MB→11.8MB（-21%，单张 31→24KB）。
   注意 compress_covers.py 是就地重压，重复跑会累积损失。
4. **站内小图转 webp**（tools/optimize_ui_assets.py）：
   miku 42.4→2.1KB、webtitle 94.4→14.2KB、blblfmj 9.1→4.6KB、
   favicon 94.4→8.2KB（64px）。这些图每页都加载，合计省 ~126KB。
   favicon 仍用 png（webp favicon 兼容性差）。
5. **首页底部网格**：手机端 CSS 隐藏 `#homeLatest`，但 display:none 不阻止
   图片下载，改成 cols()<=3 时干脆不渲染，跨断点再补。
6. **登录页裁剪依赖**：不再引 data.js/nav/footer/card（少 60KB），
   app.js 对 nav/footer/card/mascot 逐个判空，缺模块不打断启动。

**效果（线上实测）**：
| 指标 | 优化前 | 优化后 |
|---|---|---|
| DOMContentLoaded | 20.5s | **2.2s** |
| FCP | 2.45s | 1.95s |
| 首页传输量 | 544KB（15s 时未完成） | 470KB（全部完成） |
| 图片 pending | 38 张 | 0 张 |
| 手机端 | — | DCL 3.0s / 341KB / 全图 12.3s |

**遗留**：loadEvent 仍 12~14s，瓶颈是 GitHub Pages 带宽（~30KB/s），
代码层已接近极限。彻底解决要换托管（EdgeOne Pages / Cloudflare Pages），
调优再往下只能减首屏图和首屏卡片数。

**顺手修的 bug**：首屏图分档后 hero-fx 的遮罩路径按图名推导，变成
`lliij-2-1400-hair.webp`（404），手机/中屏的头发飘动一直失效（静默降级）。
改为先剥 `-\d+` 宽度后缀再拼 `-hair.webp`，遮罩按归一化 UV 采样可与底图不同分辨率。
