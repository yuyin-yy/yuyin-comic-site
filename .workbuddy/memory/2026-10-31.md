# 2026-10-31 · 漫画网站前端重构（v2）

## 背景
旧站为手写 Bootstrap 4 多页站点：5 个 HTML 各自内联 `<style>`、卡片与导航页脚逐页复制、
`inedx.html` 拼写错误、`/public/imgs` 绝对路径失效、搜索框无逻辑、登录表单校验选错元素。

## 完成内容
- 前端整体重写为「单一设计系统 + 数据驱动渲染」：
  - `public/css/site.css`：设计变量（--ink/--paper/--accent 等）、组件、响应式断点 1080/900/720/460。
  - `public/js/data.js`：34 部作品数据源（标题、作者、封面、标签、地区、评分、状态、最新话、简介、外链、更新时间、热度），页面全部由此渲染。
  - `public/js/site.js`：注入导航/页脚、卡片/榜单渲染、搜索联想、追漫收藏（localStorage `yy-favs`）、
    滚动进场动画、Toast、登录态（`yy-token`，解析 JWT payload 取用户名）。
- 页面：`index.html`（Hero+人气推荐+排行榜+最近更新）、`index01.html`（筛选/排序/加载更多）、
  `index02.html`（详情，支持 `?id=`）、`Login.html`（登录/注册双 Tab）、`my.html`（追漫清单+推荐）。
- 移除 Bootstrap/jQuery 及 4 个旧 CSS（已归档到 `backup/public-20261031/lib`），样式体积从 ~180KB 降至 ~30KB。
- 服务端 `server.js` 重写：补 `express.static`、修正 JWT 密钥不一致（旧版 `/api/protected` 必然 403）、
  改用 mysql2/promise 连接池、统一 JSON 错误、输入校验、DB 不可用时降级不退出。
- 新增 `.gitignore`（屏蔽 sql.env 等），删除误命名的 `file.gitignore`。

## 关键约定
- 数据只改 `public/js/data.js`；新增作品追加一条记录即可，封面放 `public/imgs/<1-4>/`。
- 页面不再写内联样式，新增样式进 `site.css`；不再引入 UI 框架。
- 旧版源码在 `backup/`，可对照回滚。
- 运行：`npm start`（默认 3000，静态站点+接口）；数据库表 `users(id, username, password)`。

## 验证

## 限流补充结论（18:30 实测）
- 瓜子漫画的封禁不是几分钟级别：首轮被封后连续 52 分钟（14 次探测）仍 403，
  **详情页与列表页一起封**，且换 UA / 移动 UA / Googlebot UA 均无效 → 属 IP 级封禁。
- 公共 CORS 代理（allorigins、codetabs、corsproxy.io）全部拿不到内容（522/403），
  r.jina.ai 在当前网络环境不可达（000），不能用代理绕开。
- 唯一可行的是换出口：WebFetch 走的是另一条出口，能正常拿到详情页（但只返回正文摘要，
  章节 id 不完整），不适合批量补数据，只能做单页抽查。
- 结论：补全只能"等解封 + 小批量"，`tools/guazi_loop.py --interval 600 --batch 45` 是当前唯一稳妥路径。

## 重要教训：抓取把本机公网 IP 封了（19:05）
- 用 4 并发快速抓详情（约 190 个）后，源站开始 403；随后**列表页、首页全部 403**。
- 这是 CDN/WAF 的 **IP 级封禁**：浏览器、curl、脚本、用户本人访问都一起被挡，
  换 UA、加 Cookie、公共代理都无效；只有换出口 IP（手机热点）能立刻恢复。
- 处置：立刻 kill 掉 `guazi_loop.py`，不再对本机网络发起任何请求；等待数小时自动解封。
- 以后规则：**单机抓取上限约 120~150 个详情/次，单并发、间隔 ≥3s，抓完停几小时**；
  绝不要挂"每 10 分钟探测一次"的循环——探测请求本身会延长封禁。
